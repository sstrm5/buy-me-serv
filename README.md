# Купи-мне!

Веб-приложение для совместных покупок: если кто-то из знакомых идёт в магазин, можно попросить его купить продукты заодно.

## Как это работает

1. **Заказчик составляет список.** Указывает товары, количество, максимальную цену и правила замены, выбирает получателей запроса и срок его действия.
2. **Покупатель создаёт закупку.** Выбирает реквизиты для перевода и добавляет один или несколько адресованных ему запросов. Доступные запросы сгруппированы по отправителям.
3. **В магазине покупатель собирает товары.** Отмечает результат по каждой позиции, фактическое количество, стоимость и замену. Введённые данные сохраняются в браузере при обновлении страницы.
4. **После закупки заказчик видит результат.** Доступны итоговая сумма, реквизиты для перевода и фото чека, если оно приложено. Если что-то пошло не по списку, можно завершить запрос или создать повторный, отредактировать и отправить заново.
5. **Участники отмечают возврат денег.** Статус расчётов отображается в запросе, закупке и карточках списков.

## Возможности

| Раздел | Что можно сделать |
| --- | --- |
| Профиль | Зарегистрироваться, войти, добавить реквизиты и выбрать основные |
| Друзья | Найти пользователя по логину, отправить и принять заявку |
| Запросы | Создать и отредактировать список, выбрать получателей, просмотреть отправленные и полученные запросы |
| Закупки | Объединить запросы, начать сборку, указать результаты и завершить поход |
| Расчёты | Посмотреть суммы и реквизиты, отметить возврат денег |
| Оформление | Переключить светлую и тёмную темы в профиле; выбор хранится в cookie |

### Правила сборки

- Покупателю доступны только действующие запросы, в которых его указали получателем.
- До начала сборки запрос может находиться в нескольких закупках. При старте он закрепляется за одним покупателем и удаляется из остальных закупок.
- Сборка начинается сразу для всех запросов в закупке.
- Завершить закупку можно после обработки каждого товара.
- Все товары куплены как просили — запрос завершается. Если есть изменения или пропуски, он ждёт решения заказчика.
- Временные реквизиты используются только для одной закупки и не добавляются в профиль.

## Технологии

**Java 21 · Jakarta Servlet / JSP / JSTL · Spring JDBC · PostgreSQL · Maven · Apache Tomcat 11**

## Локальный запуск

### 1. Подготовить окружение

Понадобятся JDK 21, Maven, PostgreSQL и Apache Tomcat 11.

Нужно создать базу PostgreSQL и пользователя с правом создания таблиц в ней.

### 2. Настроить подключение

В корне проекта нужно скопировать пример конфигурации:

```sh
cp .env.example .env
```

В файле нужно указать параметры подключения:

```dotenv
POSTGRES_DB_URL=jdbc:postgresql://localhost:5432/db
POSTGRES_DB_USERNAME=your_user
POSTGRES_DB_PASSWORD=your_password
```

Файл `.env` исключён из Git. Схема базы создаётся автоматически при запуске приложения из `src/main/resources/db/postgres/schema.sql`.

### 3. Собрать приложение

```sh
mvn clean package
```

Результат сборки: `target/oris-semestr-work-1.0-SNAPSHOT.war`.

### 4. Запустить в Tomcat

В IntelliJ IDEA нужно настроить локальный Tomcat 11, добавить WAR или exploded-артефакт и задать **Application context: `/sem`**. При запуске из папки проекта приложение найдёт `.env`.

При развёртывании вне папки проекта нужно передать `POSTGRES_DB_URL`, `POSTGRES_DB_USERNAME` и `POSTGRES_DB_PASSWORD` как переменные окружения процесса Tomcat.

После запуска нужно открыть [http://localhost:8080/sem/](http://localhost:8080/sem/).

## Проверки

Обычные тесты:

```sh
mvn test
```

Интеграционные тесты полного цикла закупки на PostgreSQL:

```sh
mvn test -Dpurchase.integration=true
```

Для интеграционных тестов требуется подключение из `.env` и право создания схем. Тесты создают отдельную временную схему и удаляют её после выполнения.
